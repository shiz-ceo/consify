**docsivi** is a foundation for documentation sites. You do not copy a template and then maintain it. You write a configuration file, your pages and, when you need them, a few components. The rest is a package you update with one command.

```ts title="docs.config.ts"
import { defineConfig } from "docsivi";

export default defineConfig({
  site: { name: "My project" },
  i18n: { languages: ["en", "ru"] },
  blog: { authors: { me: { name: "Me" } } },
});
```

That file, a `content/` folder and two three-line config files are the whole project. There is no `app/` folder, no routes to keep in sync and no forked layout to merge when the core improves.

## Who it is for

- Teams that want a good documentation site without owning a design system and a build pipeline.
- Projects with several languages or several versions of the docs, where the usual approach is a pile of copies.
- People who want to change the look and the behavior later without forking.

If you need a page that has nothing to do with documentation, docsivi is not the right tool. It is built for content that lives in files.

## How it is built

docsivi puts [Fumadocs](https://fumadocs.dev) (content, search, UI) on [React Router](https://reactrouter.com) and [Vite](https://vite.dev), validates the configuration with [Zod](https://zod.dev), and runs on [Bun](https://bun.sh). You do not need to know any of them to use it, but everything they can do is still available when you do.
