---
title: Серверный и статический режимы
description: Два способа запустить сайт
---

`deploy.mode` определяет, как сайт работает в продакшене.

```ts title="docs.config.ts"
deploy: { mode: "server" }, // or "static"
```

| | `server` (по умолчанию) | `static` |
| --- | --- | --- |
| Результат | Node-сервер (`build/server`) и файлы (`build/client`) | Обычные файлы (`build/client`) |
| Хостинг | Всё, что запускает Node: VPS, Docker, платформа | Любой статический хостинг: S3, GitHub Pages, CDN |
| Страницы | Рендерятся по запросу, а также предварительно при сборке | Предварительно рендерятся при сборке, затем одностраничное приложение |
| Поиск | Серверный эндпоинт `/api/search` | Индексный файл, поиск выполняется в браузере |
| Редиректы | Настоящие HTTP-редиректы (`/` на язык, `/docs` на версию) | Небольшие страницы с мгновенным редиректом |

## Что общего у обоих режимов

- Каждая страница на каждом языке рендерится при сборке, поэтому HTML полностью готов для поисковых систем и превью в соцсетях.
- Собираются `sitemap.xml`, `robots.txt`, `llms.txt` и `llms-full.txt`.
- В результате сборки нет черновиков и постов с датой в будущем.

## Что выбрать

Используйте `static`, когда это возможно. Это дешевле, быстрее и не требует постоянно работающего сервера. Используйте `server`, если нужны настоящие редиректы или вы хотите держать всё на собственной машине через `consify start`.

<Callout type="warn">
  У статического сайта нет сервера, поэтому `/` не может ответить HTTP-редиректом. Он открывает
  страницу, которая сразу отправляет читателя на нужный язык.
</Callout>

Команды, заметки о хостинге и `basePath` см. в разделе [Деплой](/docs/v0/deployment).
