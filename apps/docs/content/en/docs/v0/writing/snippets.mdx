---
title: Snippets
description: One file of code or text, shared by the pages of every language
---

A code example is the same in every language of the docs, and yet each translation has a copy of it: a fix made in one copy is missing in the others. A **snippet** is a file of the folder `snippets/` that a page puts in place with a tag:

```mdx
<Snippet id="db/connect" title="db.ts" />
```

The tag is replaced when the page is compiled, before anything else: the code is highlighted, Twoslash checks it, and the search, `llms.txt` and the link cards see it as if it were written on the page.

## Turn it on

```ts title="docs.config.ts"
docs({ snippets: true });
```

The files are in `snippets/`, next to `content/`. `snippets: { dir: "shared" }` is another folder of the project. With snippets off, a page with `<Snippet>` stops with a message that says how to turn them on.

## The folder

```txt
snippets/
  v1/                    the folder of a version (the version of the page)
    db/connect.ts        id "db/connect", for every language
    prereqs.mdx          id "prereqs"
    ru/prereqs.mdx       the Russian variant of "prereqs"
    en/prereqs.mdx       the English variant
  v2/
  WITHOUT_VERSION/       for the pages that have no version
```

The **id** of a snippet is its path inside the folder of the version, without the extension: `db/connect`. It never has the version or the language in it. A folder of a version that is named like a language of the site (`ru/`, `en/`) is the folder of that language, so an id cannot start with the code of a language. The folders of `snippets/` are the versions of the docs and `WITHOUT_VERSION` (the docs with no versions use it too); `consify check` fails on any other one.

## Which file a page gets

For a page in the language `ru` of the version `v1`, `<Snippet id="prereqs" />` is the first of:

1. `snippets/v1/ru/prereqs.*`: the variant of the language of the page;
2. `snippets/v1/prereqs.*`: the file for every language;
3. `snippets/v1/en/prereqs.*`: the variant of the default language.

When none is there, the page stops with the paths that were tried. `version="v1"` (or `version="WITHOUT_VERSION"`) takes the snippet from another folder; by default it is the version of the page. A page shown without a translation is the original, so it gets the snippets of the default language.

## The props of Snippet

| Prop | What it does |
| --- | --- |
| `id` | The snippet, `"db/connect"`; `"db/connect#open"` takes a region of it |
| `version` | The folder to read, the version of the page by default |
| `title` | The title of the code block (`title="db.ts"`) |
| `highlight` | Highlighted lines, `"2,4-5"` |
| `lineNumbers` | Line numbers; `lineNumbers={10}` starts at 10 |
| `twoslash` | Compiles the code and shows the types on hover |
| `noCopy` | No copy button |
| `lang` | The language of the block instead of the one of the extension; it also shows an `.mdx` file as code |
| `meta` | Anything else, as it is written after the language of a fenced block: `meta='tab="npm"'` |

Every prop except `id` and `version` is for a code snippet. The value is a text (`title="db.ts"`) or a literal (`lineNumbers={10}`), not an expression. The tag is a block of its own: it cannot be inside a sentence, and it has no children.

## Code snippets

A file of code (`.ts`, `.tsx`, `.json`, `.sh`, `.py`, `.css`, `.yaml`…: any language the highlighter knows) becomes a fenced code block; its language is its extension (`.mjs` is `js`, `.mts` is `ts`). The file is only shown, never run: a `.tsx` snippet is not a component.

Everything a fenced block does works: the notations in the comments of the file (`// [!code highlight]`, `// [!code ++]` and `// [!code --]`, `// [!code focus]`, `// [!code word:name]`), and in a `twoslash` block `// ^?`, `// @errors: 2322` and `// ---cut---`. See [Code blocks](/docs/v0/writing/code-blocks).

## Regions

`id="file#name"` shows only the lines between `// #region name` and its `// #endregion`, without their common indent. `# #region` (shell, Python, YAML), `<!-- #region -->` and `/* #region */` work too; regions can be inside each other. The lines of the markers are never shown, not even when the whole file is. A region that is not in the file stops the page.

This site has the plugin of [Plugins](/docs/v0/customizing/plugins) as a snippet, `snippets/v0/github-alerts.ts`; its region `types` is:

<Snippet id="github-alerts#types" title="custom/plugins/github-alerts.ts" />

```mdx
<Snippet id="github-alerts#types" title="custom/plugins/github-alerts.ts" />
```

## Text snippets

An `.mdx` (or `.md`) file is put on the page as text: its paragraphs, lists, code blocks and components (`<Callout>`, `<Tabs>`, `<TypeTable>`, the components of `custom/components/`) are the page's own.

- Its `import` lines go to the top of the page. The same import on the page and in the snippet is kept once; an import of a name that the page has for something else is an error.
- It can have `<Snippet>` tags of its own, read for the language and version of the page. Snippets that include each other are an error.
- It has **no headings**: a heading in a snippet is an error. The headings of a page, and their ids in the [anchors registry](/docs/v0/writing/headings-and-anchors), are written on the page; put the snippet under one.
- It has no front matter: one is an error.
- A relative link in it is read from the page it is put on, and is not checked by `consify check`. Use the address of the site in a snippet: `/docs/v0/writing`.

A `<Snippet>` works in `.mdx` pages; in an `.md` page it is plain HTML.

## Languages

A code snippet is one file for every language; when its comments have to be translated, put a variant in the folder of the language: `snippets/v1/ru/db/connect.ts`. A variant changes the comments only: `consify check` warns when two variants of a code snippet differ in anything but the comments (`//`, `/* */`, `<!-- -->`, and `#` in shell, Python and YAML; a `//` inside a string is taken for a comment too). Translate a text snippet the same way, `snippets/v1/ru/prereqs.mdx`.

## What is checked

`consify check` and `consify build` (the build stops on an error; `--no-snippets-check` skips it, then the page that fails stops the build) tell:

| What | Result |
| --- | --- |
| A `<Snippet>` with no file, with a region that is not in the file, or with a wrong prop | error, with the paths that were tried |
| Snippets that include each other | error |
| A heading, front matter or an `export` in a text snippet, an import that conflicts with the page | error |
| A folder of `snippets/` that is not a version or `WITHOUT_VERSION`, a file with no version folder | error |
| A file that no page uses | warning |
| Two language variants of a code snippet that differ in more than their comments | warning |

`consify snippets check` is the check alone.

## Find repeated code

```bash
consify snippets find --min-lines 5
```

lists the code blocks that are the same, byte for byte, on two pages or more (a translation is another page), with where they are, a file for the snippet and the tag to replace them with. It changes nothing; `--min-lines` is 3 by default.

## An example

A page in two languages shows how to connect, and the Russian one has its comments in Russian:

```ts title="snippets/v1/db/connect.ts"
import { createClient } from "./client";

// #region open
// one client for the whole app
const client = createClient({ url: process.env.DATABASE_URL });
await client.connect();
// #endregion
```

```ts title="snippets/v1/ru/db/connect.ts"
import { createClient } from "./client";

// #region open
// один клиент на всё приложение
const client = createClient({ url: process.env.DATABASE_URL });
await client.connect();
// #endregion
```

Both `content/en/docs/v1/guide.mdx` and `content/ru/docs/v1/guide.mdx` have the same tag, under a heading of their own:

```mdx
<Snippet id="db/connect#open" title="db.ts" />
```

A fix of the code is made in `snippets/v1/`, once; `consify check` warns when the Russian variant is left behind.
