---
title: Тестирование фич
description: Тестируем опции, адреса, ссылки, функции load и контент фичи через bun test
---

Фича это обычные данные: `defineFeature` возвращает объект с её страницами, файлами и настройками контента. Поэтому большую часть фичи можно тестировать без браузера и без запущенного сайта. Вы вызываете её функции напрямую и проверяете, что они вернули.

Эта страница показывает, как это делать. Примеры взяты из тестов `@consify/core`, `@consify/blog`, `@consify/docs` и `@consify/api-reference`, а также из пакета `consify-status` со страницы [Фича как пакет](/docs/v0/features/packages).

## Что тестировать

| Что | Инструмент | Что ловит |
| --- | --- | --- |
| Опции | Сама функция-фабрика | Неверную опцию, которая не останавливает сайт, плохое сообщение об ошибке |
| Ссылки | `linkCatalog` | Пропавшую или непереведённую ссылку в шапке |
| Адреса | `siteAddresses` | Страницу, которая не собирается, пропущенный `paths`, неверный адрес |
| Данные | `createLoadContext` + `load` | Неверные данные, пропущенный 404, неверное перенаправление |
| Файлы | `createLoadContext` + `load` файла | Неверный JSON или ленту |
| Контент | `createContent`, `bundledSource` | Проверку front matter, фильтры, порядок, переводы |
| Чистая логика | Прямой импорт | Сортировку, фильтры, разбор |
| Страницы | `consify dev`, `consify check`, `consify build` | То, что видно глазами: раскладку, языки, тему |

Тестируйте снизу вверх. Сначала чистую логику: она быстрая и не требует подготовки. Потом фичу через функции core. Страницы в последнюю очередь, на настоящем сайте.

## Подготовка

Тесты запускаются через `bun test`. Кладите их в `test/*.test.ts`:

```bash
bun test
bun test --watch
bun test test/status.test.ts
```

Функции для тестов берутся из двух точек входа:

| Импорт | Откуда |
| --- | --- |
| `defineConfig`, `defineFeature`, `page`, `linkCatalog`, `z`, типы | `@consify/core` |
| `createLoadContext`, `siteAddresses`, `createContent`, `bundledSource`, `diskSource` | `@consify/core/node` |

Большинству тестов нужна папка проекта: контент, файл с данными. Создавайте новую временную папку для каждого теста и удаляйте её после:

```ts title="test/notes.test.ts"
import { afterEach, beforeEach } from "bun:test";
import { mkdirSync, mkdtempSync, rmSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { dirname, join } from "node:path";

let cwd: string;
beforeEach(() => {
  cwd = mkdtempSync(join(tmpdir(), "consify-notes-"));
});
afterEach(() => {
  rmSync(cwd, { recursive: true, force: true });
});

/** `write("content/en/notes/a.mdx", "...")`: a file of the temp project. */
function write(path: string, text: string) {
  mkdirSync(dirname(join(cwd, path)), { recursive: true });
  writeFileSync(join(cwd, path), text);
}
```

Каждая функция, которая читает проект, принимает эту папку: `siteAddresses(config, cwd)`, `createLoadContext({ ..., cwd })`, `createContent({ ..., cwd })`.

<Callout type="warn" title="Не тестируйте на настоящем проекте">
Без `cwd` эти функции читают текущую папку. Тест, который читает ваш настоящий `content/`, сломается, как только кто-то поправит страницу. Всегда передавайте временную папку, даже пустую.
</Callout>

## Конфиг для теста

Фичу тестируют внутри конфига, так же, как её использует сайт. `defineConfig` проверяет конфиг так же, как `docs.config.ts`:

```ts
import { defineConfig } from "@consify/core";
import { status } from "../src/index.ts";

const site = { name: "D", url: "https://d.example" };
const services = [
  { id: "api", name: "API" },
  { id: "workers", name: "Workers" },
];
const config = (...features: ReturnType<typeof status>[]) =>
  defineConfig({ site, i18n: { languages: ["en", "ru"] }, features });
```

Берите два языка. Многие ошибки видны только на втором: непереведённый заголовок, адрес с неверным языком.

Задайте `site.url`, когда тестируете `url()` из контекста загрузки или всё, что строит абсолютные адреса (ссылку «поделиться», ленту).

## Опции

Неверная опция должна останавливать сайт и называть себя:

```ts
test("wrong options stop with their name", () => {
  expect(() => status({ source: "./status.json", services: [] })).toThrow(
    /status\(\): services: list at least one service/,
  );
  expect(() => status({ source: "./s.json", services, perPage: 3 } as never)).toThrow(
    /status\(\)/,
  );
});
```

`as never` позволяет передать опцию, которую не пропускает TypeScript. Пользователь обычного JavaScript может сделать то же самое.

`defineFeature` тоже проверяет свой вход. Тест core показывает, что он отвергает:

```ts
expect(() => defineFeature({ id: "shop", pages: { item: View } })).toThrow(/start with "\/"/);
expect(() => defineFeature({ id: "Shop" })).toThrow(/lowercase/);
```

## Ссылки

`linkCatalog(config, lang)` перечисляет все места, на которые фичи предлагают ссылаться: главную страницу каждой фичи с `title`, затем `<id>:llms`, `<id>:rss` и то, что добавляет `links`. Из этого списка строятся шапка и подвал.

```ts
import { linkCatalog } from "@consify/core";

test("offers a translated link", () => {
  const c = config(status({ source: "./status.json", services }));
  expect(linkCatalog(c, "ru").map((l) => [l.id, l.title, l.url])).toEqual([
    ["status", "Статус", "/ru/status"],
  ]);
});
```

Блог предлагает ещё и свою ленту:

```ts
expect(linkCatalog(config(blog()), "ru").map((l) => [l.id, l.title, l.url])).toEqual([
  ["blog", "Блог", "/ru/blog"],
  ["blog:rss", "RSS", "/ru/blog/rss.xml"],
]);
```

## Адреса

`siteAddresses(config, cwd)` перечисляет все адреса сайта: каждую страницу, перенаправление и файл каждой фичи, на каждом языке, с подставленными параметрами. Этим же списком пользуются пререндеринг, карта сайта и `consify check`. Если адреса в нём нет, статический сайт его не соберёт.

У каждого элемента есть `feature`, `key` (адрес внутри фичи, `"/:service"`), `kind` (`page`, `redirect` или `file`), `lang`, `url` и `copy: true` для страницы, показанной без перевода.

```ts
import { siteAddresses } from "@consify/core/node";

test("a page per service in every language, and the JSON file", async () => {
  const c = config(status({ source: "./status.json", services }));
  const urls = (await siteAddresses(c, cwd))
    .filter((a) => a.feature.id === "status")
    .map((a) => `${a.kind} ${a.url}`);
  expect(urls).toEqual([
    "page /en/status",
    "page /en/status/api",
    "page /en/status/workers",
    "file /en/status/status.json",
    "page /ru/status",
    "page /ru/status/api",
    "page /ru/status/workers",
    "file /ru/status/status.json",
  ]);
});
```

Фильтруйте по `feature.id`: в списке есть и встроенная главная страница сайта.

Если у фичи есть контент, отдельно проверьте статический режим. Сервер сам отвечает на поисковые запросы, и только статический сайт получает поисковый индекс в виде файла:

```ts
test("a static site gets the search index as a file", async () => {
  const built = defineConfig({ ...config, deploy: { mode: "static" } });
  const urls = (await siteAddresses(built, cwd)).map((a) => a.url);
  expect(urls).toContain("/en/notes/search.json");
});
```

<Callout type="warn" title="Страница с параметром без paths">
У страницы с `:param` или `*` в адресе, у которой нет `paths` (и нет `entry: true`), в этом списке **нет** адресов. Сервер всё равно отрисует её по запросу, а на статическом сайте её не будет вовсе. Тест `siteAddresses` это ловит.
</Callout>

## Данные: load

`createLoadContext` собирает тот же контекст, который сервер передаёт в `load`: `lang`, `params`, `t`, `content`, `readFile`, `config`, `request`, `url`, `notFound` и `redirect`. Поэтому `load` можно вызвать напрямую.

```ts
import { createLoadContext } from "@consify/core/node";

test("the list reads the states from the file of the project", async () => {
  const c = config(status({ source: "./status.json", services }));
  const feature = c.features[0] as ReturnType<typeof status>;
  const list = feature.pages["/"];
  if (list?.kind !== "page" || !list.load) throw new Error("no list");
  const data = await list.load(createLoadContext({ config: c, feature, lang: "en", cwd }));
  expect(data).toEqual({
    base: "/en/status",
    services: [
      { id: "api", name: "API", state: "up" },
      { id: "workers", name: "Workers", state: "down" },
    ],
  });
});
```

Опции `createLoadContext`:

| Опция | По умолчанию | |
| --- | --- | --- |
| `config` | — | Конфиг из `defineConfig` |
| `feature` | — | Фича, чей `load` вы вызываете: её строки для `t`, её папка для `content` |
| `lang` | — | Язык страницы |
| `params` | `{}` | Параметры адреса: `{ service: "api" }`, `{ "*": "v2/guide" }` |
| `request` | `new Request("http://localhost/{lang}")` | Запрос |
| `cwd` | Текущая папка | Папка проекта: из неё читают `readFile` и `content` |
| `source` | `content/` из `cwd` на диске | Откуда берётся контент, см. [Контент без диска](#контент-без-диска) |

Берите фичу из конфига (`c.features[0]`), а не из отдельного вызова. Тогда тест использует ровно то, что использует сайт.

`feature.pages[key]` это либо страница, либо перенаправление. Проверьте `kind`, прежде чем вызывать `load`: `if (page?.kind !== "page" || !page.load) throw ...`. Заодно это сообщает TypeScript, что `load` есть.

### 404

`notFound()` бросает `Response` со статусом 404. Поймайте его:

```ts
test("an unknown service is a 404", async () => {
  const c = config(status({ source: "./status.json", services }));
  const feature = c.features[0] as ReturnType<typeof status>;
  const one = feature.pages["/:service"];
  if (one?.kind !== "page" || !one.load) throw new Error("no page");
  const context = createLoadContext({
    config: c,
    feature,
    lang: "en",
    cwd,
    params: { service: "nope" },
  });
  let error: unknown;
  try {
    await one.load(context);
  } catch (thrown) {
    error = thrown;
  }
  expect(error).toBeInstanceOf(Response);
  expect((error as Response).status).toBe(404);
});
```

### Перенаправление

`redirect(to)` бросает объект с полем `to`. Небольшая функция ловит то, что бросает функция, синхронно или асинхронно:

```ts
import { expect, test } from "bun:test";
import { defineConfig, defineFeature, page } from "@consify/core";
import { createLoadContext } from "@consify/core/node";

/** What a function throws (sync or async), `undefined` when it throws nothing. */
async function thrown(run: () => unknown): Promise<unknown> {
  try {
    await run();
  } catch (error) {
    return error;
  }
  return undefined;
}

test("load sends the reader elsewhere", async () => {
  const shop = defineFeature({
    id: "shop",
    pages: {
      "/:item": page({
        load: ({ lang, params, redirect }) =>
          params.item === "old" ? redirect(`/${lang}/shop/new`) : params.item,
        component: () => null,
      }),
    },
  });
  const config = defineConfig({ site: { name: "D" }, features: [shop] });
  const item = shop.pages["/:item"];
  if (item?.kind !== "page" || !item.load) throw new Error("no page");
  const context = createLoadContext({ config, feature: shop, lang: "en", params: { item: "old" } });
  expect(await thrown(() => item.load?.(context))).toMatchObject({ to: "/en/shop/new" });
});
```

<Callout type="warn" title="Синхронный load бросает сразу">
Если `load` не `async`, `notFound()` и `redirect()` бросают исключение раньше, чем появится какой-либо промис. `load(context).catch(...)` его не поймает. Используйте `try`/`catch` вокруг `await`, как выше.
</Callout>

У **страницы**-перенаправления (`{ redirect: ... }`) нет `load`. Вызовите её функцию:

```ts
test("a redirect", () => {
  const old = notes.pages["/old"];
  if (old?.kind !== "redirect") throw new Error("no redirect");
  expect(old.redirect({ lang: "ru", config })).toBe("/ru/notes");
});
```

### Страница записи

Страница с `entry: true` получает запись в `load` как `entry`. Сервер находит её по адресу. В тесте прочитайте её через `content.entry(slug)` и добавьте в контекст:

```ts
test("the page of an entry gets the entry", async () => {
  write("content/en/notes/a.mdx", "---\ntitle: A\n---\nHello");
  const context = createLoadContext({
    config,
    feature: notes,
    lang: "en",
    cwd,
    params: { "*": "a" },
  });
  const entry = (await context.content.entry("a")) as EntryPage;
  const one = notes.pages["/*"];
  if (one?.kind !== "page" || !one.load) throw new Error("no page");
  const data = (await one.load({ ...context, entry })) as { title: string; code: string };
  expect(data.title).toBe("A");
  expect(data.code).toContain("Hello");
});
```

Фича `notes` из этого и следующих примеров:

```ts
import { defineConfig, defineFeature, type EntryPage, page, z } from "@consify/core";

const View = () => null;

const notes = defineFeature({
  id: "notes",
  content: {
    schema: z.object({ title: z.string(), draft: z.boolean().default(false) }),
    filter: (entry) => !entry.data.draft,
    og: true,
  },
  pages: {
    "/": page({
      load: async ({ content }) => (await content.entries()).map((e) => e.slug),
      title: ({ data }) => `${data.length} notes`,
      component: View,
    }),
    "/*": page({
      entry: true,
      load: ({ entry }) => ({ title: String(entry?.data.title), code: entry?.code ?? "" }),
      component: View,
    }),
    "/old": { redirect: ({ lang }) => `/${lang}/notes` },
  },
});

const config = defineConfig({
  site: { name: "D" },
  i18n: { languages: ["en", "ru"] },
  features: [notes],
});
```

`View = () => null` достаточно: тест `load` никогда не рисует компонент.

### Заголовки и meta

`title`, `description` и `meta` страницы это функции от `data`. Вызовите их с данными, которые вернул `load`:

```ts
test("the title is made from the data", async () => {
  write("content/en/notes/a.mdx", "---\ntitle: A\n---\n");
  const list = notes.pages["/"];
  if (list?.kind !== "page" || !list.load || typeof list.title !== "function") {
    throw new Error("no list");
  }
  const context = createLoadContext({ config, feature: notes, lang: "en", cwd });
  const data = await list.load(context);
  expect(list.title({ data, lang: "en", params: {}, t: context.t })).toBe("1 notes");
});
```

## Файлы

У файла есть только `load`. Вызывайте его так же:

```ts
test("the JSON file", async () => {
  const c = config(status({ source: "./status.json", services }));
  const feature = c.features[0] as ReturnType<typeof status>;
  const file = feature.files["/status.json"];
  if (!file) throw new Error("no file");
  const body = await file.load(createLoadContext({ config: c, feature, lang: "en", cwd }));
  expect(body).toMatchObject({ services: [{ id: "api", state: "up" }, { id: "workers" }] });
});
```

`load` возвращает тело до того, как core превратит его в `Response`: объект (отправляется как JSON), строку, байты или `Response`.

## Строки

`t` из контекста загрузки сначала читает строки **своей** фичи. Две фичи могут использовать один и тот же ключ:

```ts
test("two features may use the same key: each reads its own", () => {
  const a = defineFeature({
    id: "a",
    title: ({ t }) => t("hint"),
    messages: { en: { hint: "A" } },
  });
  const b = defineFeature({
    id: "b",
    title: ({ t }) => t("hint"),
    messages: { en: { hint: "B" } },
  });
  const config = defineConfig({ site, features: [a, b] });
  expect(createLoadContext({ config, feature: a, lang: "en", cwd }).t("hint")).toBe("A");
  expect(createLoadContext({ config, feature: b, lang: "en", cwd }).t("hint")).toBe("B");
  const catalog = linkCatalog(config, "en").map((l) => l.title);
  expect(catalog).toEqual(["A", "B"]);
});
```

`t("hi", { name: "Ada" })` подставляет `{name}` в строку. Несуществующий ключ возвращается как есть, поэтому опечатка видна в тесте как сам ключ.

## Контент

`createContent` даёт `content` фичи на одном языке, без страницы. Это тот же объект, который `load` получает как `content`.

```ts
import { createContent } from "@consify/core/node";

test("entries are checked, filtered and translated", async () => {
  write("content/en/notes/a.mdx", "---\ntitle: A\n---\nText");
  write("content/en/notes/b.mdx", "---\ntitle: B\ndraft: true\n---\n");
  const ru = createContent({ config, cwd, feature: notes, lang: "ru" });
  const entries = await ru.entries();
  expect(entries.map((e) => [e.slug, e.url, e.fallback])).toEqual([["a", "/ru/notes/a", true]]);
});
```

Этот один тест проверяет четыре вещи: черновик отфильтрован, адрес правильный, русский список использует английский файл, и этот файл помечен как `fallback`.

Неверный front matter должен останавливать сайт и называть файл:

```ts
test("a wrong front matter names its file", async () => {
  write("content/en/notes/a.mdx", "---\ntitle: 3\n---\n");
  const en = createContent({ config, cwd, feature: notes, lang: "en" });
  await expect(en.entries()).rejects.toThrow(/content\/en\/notes\/a\.mdx: title/);
});
```

Другие методы `content`, которые стоит тестировать: `list(dir)`, `read(path)`, `json(path)`, `frontmatter(path)`, `mdx(path)`, `entry(slug)`, `in(lang)`. См. [Контент](/docs/v0/features/content) и [Справочник](/docs/v0/features/reference).

Если фича зависит от `i18n.fallback` сайта, протестируйте и его. С `"hide"` непереведённого файла на другом языке нет:

```ts
const hidden = defineConfig({
  site,
  i18n: { languages: ["en", "ru"], fallback: "hide" },
  features: [notes],
});
```

### Контент без диска

Собранный сервер читает контент из своего бандла, а не из `content/`. `bundledSource` делает такой источник из объекта: путь → функция, которая возвращает текст. Пользуйтесь им для быстрого теста без файлов или чтобы проверить случай с бандлом:

```ts
import { bundledSource, createContent } from "@consify/core/node";

test("the same content from a bundle, with no folder", async () => {
  const source = bundledSource({
    "/content/en/notes/a.mdx": async () => "---\ntitle: A\n---\nText",
  });
  const en = createContent({ config, cwd, feature: notes, lang: "en", source });
  expect((await en.entry("a"))?.code).toContain("Text");
});
```

`createLoadContext` и `siteAddresses` принимают тот же `source` (`siteAddresses(config, cwd, source)`).

### Адреса контента

Фича с контентом получает адреса от core: страницу на каждую запись, картинку для соцсетей на каждую запись при `og`, `llms.txt` при `llms`, ленту при `rss`. Проверяйте их через `siteAddresses`:

```ts
test("a page and a social image per entry, in every language", async () => {
  write("content/en/notes/a.mdx", "---\ntitle: A\n---\n");
  const addresses = await siteAddresses(config, cwd);
  expect(addresses.map((a) => `${a.kind} ${a.url}${a.copy ? " (copy)" : ""}`)).toEqual(
    expect.arrayContaining([
      "page /en/notes",
      "page /en/notes/a",
      "redirect /en/notes/old",
      "file /en/notes/og/a.png",
      "page /ru/notes/a (copy)",
    ]),
  );
});
```

`/ru/notes/a` это копия: английская страница, показанная на русском. Она собирается, но в карту сайта не попадает.

## Код только для сервера

`load`, который импортирует `server.ts` за условием `import.meta.env.SSR`, не работает в `bun test`: там `import.meta.env.SSR` равен `undefined`, и импорт отклоняется. Тестируйте функции `server.ts` напрямую:

```ts
import { expect, test } from "bun:test";
import { parseChangelog } from "../src/server.ts";

test("reads the versions of a changelog", () => {
  expect(parseChangelog("# Changes\n\n## 1.1.0\nFixes\n\n## 1.0.0\nFirst").map((r) => r.version))
    .toEqual(["1.1.0", "1.0.0"]);
});
```

Это ещё одна причина держать логику в обычных `.ts`-файлах: функцию без React и без контекста загрузки тестировать проще всего.

## Два экземпляра

Пакет с фичей должен работать дважды на одном сайте. Проверьте это:

```ts
test("a second one has its own id and address; the same id twice is refused", async () => {
  const c = config(
    status({ source: "./status.json", services }),
    status({ id: "uptime", title: "Uptime", source: "./status.json", services }),
  );
  expect(linkCatalog(c, "en").map((l) => [l.id, l.url])).toEqual([
    ["status", "/en/status"],
    ["uptime", "/en/uptime"],
  ]);
  expect(() =>
    config(
      status({ source: "./status.json", services }),
      status({ source: "./status.json", services }),
    ),
  ).toThrow(/duplicate feature "status"/);
});
```

Если есть контент, проверьте, что каждый экземпляр читает свою папку. В тестах `@consify/blog` функция `write(lang, slug, header, folder)` пишет пост, а `urls(config, id)` перечисляет адреса одной фичи:

```ts
test("a second blog reads its own folder", async () => {
  write("en", "one", "date: 2026-01-01", "news");
  const c = config(blog(), blog({ id: "news", title: "News" }));
  expect(await urls(c, "news")).toContain("/en/news/one");
  expect(await urls(c, "blog")).not.toContain("/en/blog/one");
});
```

## Полный файл тестов

Тесты `consify-status` со страницы [Фича как пакет](/docs/v0/features/packages), одним файлом:

```ts title="test/status.test.ts"
import { afterEach, beforeEach, describe, expect, test } from "bun:test";
import { mkdtempSync, rmSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { defineConfig, linkCatalog } from "@consify/core";
import { createLoadContext, siteAddresses } from "@consify/core/node";
import { status } from "../src/index.ts";

let cwd: string;
beforeEach(() => {
  cwd = mkdtempSync(join(tmpdir(), "consify-status-"));
  writeFileSync(join(cwd, "status.json"), '{ "api": "up", "workers": "down" }');
});
afterEach(() => {
  rmSync(cwd, { recursive: true, force: true });
});

const site = { name: "D", url: "https://d.example" };
const services = [
  { id: "api", name: "API" },
  { id: "workers", name: "Workers" },
];
const config = (...features: ReturnType<typeof status>[]) =>
  defineConfig({ site, i18n: { languages: ["en", "ru"] }, features });

describe("status()", () => {
  test("wrong options stop with their name", () => {
    expect(() => status({ source: "./status.json", services: [] })).toThrow(
      /status\(\): services: list at least one service/,
    );
    expect(() => status({ source: "./s.json", services, perPage: 3 } as never)).toThrow(
      /status\(\)/,
    );
  });

  test("offers a translated link", () => {
    const c = config(status({ source: "./status.json", services }));
    expect(linkCatalog(c, "ru").map((l) => [l.id, l.title, l.url])).toEqual([
      ["status", "Статус", "/ru/status"],
    ]);
  });

  test("a page per service in every language, and the JSON file", async () => {
    const c = config(status({ source: "./status.json", services }));
    const urls = (await siteAddresses(c, cwd))
      .filter((a) => a.feature.id === "status")
      .map((a) => `${a.kind} ${a.url}`);
    expect(urls).toEqual([
      "page /en/status",
      "page /en/status/api",
      "page /en/status/workers",
      "file /en/status/status.json",
      "page /ru/status",
      "page /ru/status/api",
      "page /ru/status/workers",
      "file /ru/status/status.json",
    ]);
  });

  test("the list reads the states from the file of the project", async () => {
    const c = config(status({ source: "./status.json", services }));
    const feature = c.features[0] as ReturnType<typeof status>;
    const list = feature.pages["/"];
    if (list?.kind !== "page" || !list.load) throw new Error("no list");
    const data = await list.load(createLoadContext({ config: c, feature, lang: "en", cwd }));
    expect(data).toEqual({
      base: "/en/status",
      services: [
        { id: "api", name: "API", state: "up" },
        { id: "workers", name: "Workers", state: "down" },
      ],
    });
  });

  test("an unknown service is a 404", async () => {
    const c = config(status({ source: "./status.json", services }));
    const feature = c.features[0] as ReturnType<typeof status>;
    const one = feature.pages["/:service"];
    if (one?.kind !== "page" || !one.load) throw new Error("no page");
    const context = createLoadContext({
      config: c,
      feature,
      lang: "en",
      cwd,
      params: { service: "nope" },
    });
    let error: unknown;
    try {
      await one.load(context);
    } catch (thrown) {
      error = thrown;
    }
    expect(error).toBeInstanceOf(Response);
    expect((error as Response).status).toBe(404);
  });

  test("the JSON file", async () => {
    const c = config(status({ source: "./status.json", services }));
    const feature = c.features[0] as ReturnType<typeof status>;
    const file = feature.files["/status.json"];
    if (!file) throw new Error("no file");
    const body = await file.load(createLoadContext({ config: c, feature, lang: "en", cwd }));
    expect(body).toMatchObject({ services: [{ id: "api", state: "up" }, { id: "workers" }] });
  });

  test("a second one has its own id and address; the same id twice is refused", async () => {
    const c = config(
      status({ source: "./status.json", services }),
      status({ id: "uptime", title: "Uptime", source: "./status.json", services }),
    );
    expect(linkCatalog(c, "en").map((l) => [l.id, l.url])).toEqual([
      ["status", "/en/status"],
      ["uptime", "/en/uptime"],
    ]);
    expect(() =>
      config(
        status({ source: "./status.json", services }),
        status({ source: "./status.json", services }),
      ),
    ).toThrow(/duplicate feature "status"/);
  });
});
```

## Тестирование страниц

Тесты выше проверяют данные, а не то, что видит читатель. Страницы проверяйте на настоящем сайте.

<Steps>
<Step>

### Запустите сайт

Добавьте фичу в `features` сайта (пакет подключите через `bun link` или установите), затем:

```bash
consify dev
```

Откройте каждую страницу фичи. Проверьте:

- каждый язык сайта: заголовок, строки, ссылки;
- светлую и тёмную тему;
- узкое окно (телефон);
- страницу, показанную без перевода, если у фичи есть контент;
- несуществующий адрес: `/en/status/nope` должен показать страницу 404.

</Step>
<Step>

### Проверьте контент

```bash
consify check
```

`consify check` строит список всех адресов (`siteAddresses`), поэтому неверный front matter, сломанный `meta.json` или исключение в `paths` его останавливают. Он также проверяет, что каждый файл контента написан на языке сайта и что у переводов те же блоки кода, ссылки и заголовки, что у оригиналов. `consify check --strict` делает отсутствующий перевод ошибкой.

</Step>
<Step>

### Соберите

```bash
consify build
```

Соберите и с `deploy.mode: "static"`, если фича должна работать на статическом сайте. Статическая сборка пререндерит каждый адрес, то есть один раз выполняет каждый `load`. Исключение там это ошибка, которую пропустил тест.

</Step>
</Steps>

## Подводные камни

| Симптом | Причина | Решение |
| --- | --- | --- |
| Тест проходит один, но падает вместе с другими | Тесты делят одну папку, или остался файл от прошлого теста | Новая папка `mkdtempSync` в `beforeEach`, удаление в `afterEach` |
| `load is not a function` | `pages[key]` это перенаправление, или у страницы нет `load` | Сначала проверьте `kind === "page"` и `load` |
| `entry` в `load` равен `undefined` | Тест его не передал | `load({ ...context, entry })` с `await context.content.entry(slug)` |
| 404 или перенаправление не ловится | `load` синхронный и бросает сразу | `try`/`catch` вокруг `await load(...)` |
| `load`, который импортирует `server.ts`, завершается ошибкой | В `bun test` `import.meta.env.SSR` не задан | Тестируйте `server.ts` напрямую |
| Русский список пуст | В `i18n.languages` тестового конфига только `en` | Добавьте второй язык |
| `url()` возвращает путь, а не URL | Не задан `site.url` | Задайте его в тестовом конфиге |
| В `siteAddresses` есть адрес другой фичи | В списке есть встроенная главная страница | Фильтруйте по `a.feature.id` |
