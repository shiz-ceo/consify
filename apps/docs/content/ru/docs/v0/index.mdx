**consify** — это основа для сайтов документации. Вы не копируете шаблон, чтобы потом его поддерживать. Вы пишете файл конфигурации, свои страницы и, когда понадобится, несколько компонентов. Всё остальное — пакеты, которые обновляются одной командой.

```ts title="docs.config.ts"
import { defineConfig } from "@consify/core";
import { docs } from "@consify/docs";
import { blog } from "@consify/blog";

export default defineConfig({
  site: { name: "My project" },
  i18n: { languages: ["en", "ru"] },
  features: [docs(), blog({ authors: { me: { name: "Me" } } })],
});
```

Этот файл, папка `content/` и два конфигурационных файла по три строки — вот весь проект. Здесь нет папки `app/`, маршрутов, которые нужно синхронизировать, и форкнутого шаблона, который придётся сливать при улучшении ядра.

## Для кого это [#who-it-is-for]

- Для команд, которым нужен хороший сайт документации без собственной дизайн-системы и конвейера сборки.
- Для проектов с несколькими языками или версиями документации, где обычно всё превращается в груду копий.
- Для тех, кто хочет позже менять внешний вид и поведение, не форкая проект.

Если вам нужна страница, не связанная с документацией, consify не подойдёт. Он создан для контента, который хранится в файлах.

## Как он устроен [#how-it-is-built]

consify ставит [Fumadocs](https://fumadocs.dev) (контент, поиск, интерфейс) поверх [React Router](https://reactrouter.com) и [Vite](https://vite.dev), проверяет конфигурацию с помощью [Zod](https://zod.dev) и работает на [Bun](https://bun.sh). Чтобы пользоваться consify, знать их не обязательно, но все их возможности остаются доступны, когда они вам понадобятся.

Прочитайте [Начало работы](/docs/v0/getting-started), чтобы увидеть весь путь от пустой папки до работающего сайта, или [Как это работает](/docs/v0/concepts) — что где лежит.
