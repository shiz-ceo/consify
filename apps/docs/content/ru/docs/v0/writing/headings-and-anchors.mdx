---

Адрес заголовка (`/docs/v0/guide#quick-start`) это его **ид**. По умолчанию ид делается из текста заголовка, поэтому русский заголовок даёт русский ид (`#быстрый-путь`), ид меняется, когда заголовок переписан, а у перевода ид не такие, как у оригинала. Ссылки на заголовок снаружи ломаются при каждой правке.

С включённым `anchors` у каждого заголовка ид написан, он английский, одинаковый во всех языках, и все ид перечислены в файле, который проверяет сборка.

## Как написать ид [#write-the-id]

Ид пишется в конце строки заголовка, в `[#…]` (не в `{#…}`: MDX читает это как выражение):

```md
## Быстрый путь [#quick-start]
```

Ид это английские слова и цифры в нижнем регистре, соединённые `-` или `.` (`quick-start`, `model.find`, `v2`): точка нужна для имени метода. Делайте его коротким, из английского заголовка, и **не меняйте потом**: именно его хранят ссылки на заголовок.

Заголовку на английском, чей собственный ид уже такое слово (`## Requirements` даёт `requirements`), метка не нужна, а ид заголовка с кодом (`` ## `client.transaction` ``) делается из кода. У перевода те же ид, что у оригинала, заголовок в заголовок: ид не переводятся.

## Реестр [#the-registry]

Ид версии перечислены в `anchors.json` в папке этой версии **языка оригинала** (`content/en/docs/v0/anchors.json`); страницы заданы путём внутри папки:

```json
{
  "getting-started.mdx": ["requirements", "create-the-project"],
  "writing/index.mdx": ["what-you-can-write"]
}
```

Новая версия начинается копией папки предыдущей, реестр уходит вместе с ней. Файл делает `consify anchors sync`, а люди читают его в диффе: новый ид в нём это решение иметь такой адрес.

## Что проверяется [#what-is-checked]

`consify check` и `consify build` (сборка останавливается на ошибке; `--no-anchors-check` пропускает проверку) сообщают:

| Что | Результат |
| --- | --- |
| Заголовок без своего ид, чей собственный ид не простое английское слово | ошибка (`missing`) |
| Ид, которого нет в реестре, которого нельзя писать так, или который на странице дважды | ошибка (`unknown`) |
| Ссылка (`./page.mdx#id`, `#id`) на ид, которого нет в реестре этой страницы | ошибка (`links`) |
| Ид реестра, которого нет ни на одной странице оригинала | предупреждение (`unused`): заголовок удалён или переименован, ссылки на него потеряны |
| Ид реестра, которого нет у перевода | предупреждение (`translated`) |

Каждое правило в `anchors` у `docs()` это `"error"`, `"warn"` или `"off"`; `anchors: true` это значения из таблицы. Проверяются только ссылки на страницу по её файлу (`./page.mdx#id`) и на ту же страницу (`#id`); адрес сайта (`/en/docs/page#id`) не проверяется.

## Команды [#the-commands]

`consify anchors add` пишет `[#id]` у заголовков, которым он нужен: заголовок на языке оригинала получает ид английскими буквами (`Быстрый путь` → `bystryy-put`), перевод получает ид заголовка с тем же местом в оригинале (число заголовков должно совпадать). Заодно меняет ссылки на старые ид. Посмотрите результат и улучшите ид: `consify anchors add --dry-run` только показывает, `--lang ru` это один язык.

`consify anchors sync` пишет реестр по заголовкам оригинала (`--prune` ещё убирает ид, которых нет ни на одной странице, `--dry-run` показывает). Файл пишется так, как Biome и Prettier пишут JSON (ширина строки из `biome.json`), поэтому форматер в нём ничего не меняет. `consify anchors check` это одна проверка.

## Как включить [#turn-it-on]

```ts title="docs.config.ts"
docs({ anchors: true });
```

Дальше `consify anchors add`, `consify anchors sync` и `consify check`. С этого момента новый заголовок это новый ид в реестре: напишите `[#id]`, запустите `consify anchors sync`, и дифф покажет новый адрес.
