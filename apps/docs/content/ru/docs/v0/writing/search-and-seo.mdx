## Поиск [#search]

Поиск включён в каждом разделе, у которого есть контент. Каждый раздел ищет по своим страницам: диалог принадлежит разделу, в котором находится читатель, и везде выглядит одинаково. Поле стоит вверху боковой панели, Cmd/Ctrl+K открывает диалог:

- **Документация**: диалог ищет по страницам. В режиме `server` он обращается к `/{lang}/docs/search.json`; в режиме `static` по тому же адресу лежит файл индекса, который браузер скачивает и ищет в нём сам.
- **Блог**: на его страницах Cmd/Ctrl+K ищет по записям (`/{lang}/blog/search.json`). На странице списка есть ещё поле поиска, которое фильтрует записи, и фильтр по категориям.
- **Справочник API**: поле открывает поиск Scalar.
- Собственный раздел ищется так же, если у него есть `content`. Без контента поиска у него нет, пока он не принесёт свой (`search: { useSearch, open }`): см. [Свои разделы](/docs/v0/features).

На малых экранах боковая панель открывается кнопкой, и поле лежит в ней. Убрать раздел из диалога можно через `content: { search: false }`.

## Sitemap и robots [#sitemap-and-robots]

`/sitemap.xml` перечисляет все страницы всех разделов: страницы документации, опубликованные записи блога, страницы ваших разделов. Для него нужен `site.url`. `/robots.txt` разрешает всё и указывает на sitemap.

## Мета-теги [#meta-tags]

У каждой страницы есть заголовок, описание, canonical-ссылка, ссылки на переводы (`hreflang`), а также теги Open Graph и Twitter. Для страницы из файла контента ядро заполняет их из front matter. У записей блога есть ещё теги `article:*`, а в head блога — ссылка на RSS.

## llms.txt

`/{lang}/docs/llms.txt` перечисляет страницы документации, а `/{lang}/docs/llms-full.txt` содержит всю документацию одним простым текстом. Ими могут пользоваться языковые модели и инструменты, читающие документацию. Сослаться на него из шапки можно по id `docs:llms`. Отключаются через `llmsTxt: false` в `docs()`. Собственный раздел получает такие же файлы с `content: { llms: true }`.

## Картинки для соцсетей [#social-images]

`/{lang}/docs/og/<page>.png` — сгенерированная картинка с заголовком и описанием страницы (`index.png` для `index.mdx`). У записей блога есть `/{lang}/blog/og/<slug>.png`. Картинки документации отключаются через `og: false` в `docs()`. Собственный раздел получает их с `content: { og: true }`.
