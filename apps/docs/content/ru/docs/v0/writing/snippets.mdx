---
title: Сниппеты
description: Один файл кода или текста на страницы всех языков
---

Пример кода одинаков во всех языках документации, и всё же у каждого перевода своя его копия: исправление в одной копии не попадает в другие. **Сниппет** это файл папки `snippets/`, который страница вставляет тегом:

```mdx
<Snippet id="db/connect" title="db.ts" />
```

Тег заменяется при компиляции страницы, раньше всего остального: код подсвечивается, Twoslash его проверяет, а поиск, `llms.txt` и карточки ссылок видят его так, будто он написан на странице.

## Как включить [#turn-it-on]

```ts title="docs.config.ts"
docs({ snippets: true });
```

Файлы лежат в `snippets/`, рядом с `content/`. `snippets: { dir: "shared" }` задаёт другую папку проекта. Когда сниппеты выключены, страница с `<Snippet>` останавливается с сообщением, как их включить.

## Папка [#the-folder]

```txt
snippets/
  v1/                    the folder of a version (the version of the page)
    db/connect.ts        id "db/connect", for every language
    prereqs.mdx          id "prereqs"
    ru/prereqs.mdx       the Russian variant of "prereqs"
    en/prereqs.mdx       the English variant
  v2/
  WITHOUT_VERSION/       for the pages that have no version
```

**Ид** сниппета это его путь внутри папки версии, без расширения: `db/connect`. В нём никогда нет ни версии, ни языка. Папка версии, названная как язык сайта (`ru/`, `en/`), это папка этого языка, поэтому ид не может начинаться с кода языка. Папки `snippets/` это версии документации и `WITHOUT_VERSION` (её берёт и документация без версий); на любой другой `consify check` падает.

## Какой файл получит страница [#which-file-a-page-gets]

Для страницы на языке `ru` версии `v1` тег `<Snippet id="prereqs" />` это первый из:

1. `snippets/v1/ru/prereqs.*`: вариант языка страницы;
2. `snippets/v1/prereqs.*`: файл для всех языков;
3. `snippets/v1/en/prereqs.*`: вариант языка по умолчанию.

Если нет ни одного, страница останавливается со списком путей, которые проверены. `version="v1"` (или `version="WITHOUT_VERSION"`) берёт сниппет из другой папки; по умолчанию это версия страницы. Страница, показанная без перевода, это оригинал, поэтому она получает сниппеты языка по умолчанию.

## Пропсы Snippet [#the-props-of-snippet]

| Пропс | Что делает |
| --- | --- |
| `id` | Сниппет, `"db/connect"`; `"db/connect#open"` берёт его регион |
| `version` | Папка, из которой читать, по умолчанию версия страницы |
| `title` | Заголовок блока кода (`title="db.ts"`) |
| `highlight` | Подсвеченные строки, `"2,4-5"` |
| `lineNumbers` | Номера строк; `lineNumbers={10}` начинает с 10 |
| `twoslash` | Компилирует код и показывает типы при наведении |
| `noCopy` | Без кнопки копирования |
| `lang` | Язык блока вместо языка расширения; заодно показывает файл `.mdx` как код |
| `meta` | Всё остальное, как пишется после языка в блоке кода: `meta='tab="npm"'` |

Все пропсы, кроме `id` и `version`, для сниппета кода. Значение это текст (`title="db.ts"`) или литерал (`lineNumbers={10}`), не выражение. Тег это отдельный блок: он не может стоять внутри предложения и не имеет детей.

## Сниппеты кода [#code-snippets]

Файл кода (`.ts`, `.tsx`, `.json`, `.sh`, `.py`, `.css`, `.yaml`…: любой язык, который знает подсветка) становится блоком кода; его язык это расширение (`.mjs` это `js`, `.mts` это `ts`). Файл только показывается и никогда не выполняется: сниппет `.tsx` не компонент.

Работает всё, что умеет обычный блок кода: нотации в комментариях файла (`// [!code highlight]`, `// [!code ++]` и `// [!code --]`, `// [!code focus]`, `// [!code word:name]`), а в блоке `twoslash` ещё `// ^?`, `// @errors: 2322` и `// ---cut---`. См. [Блоки кода](/docs/v0/writing/code-blocks).

## Регионы [#regions]

`id="file#name"` показывает только строки между `// #region name` и его `// #endregion`, без общего отступа. Работают и `# #region` (shell, Python, YAML), `<!-- #region -->` и `/* #region */`; регионы могут быть вложены. Строки маркеров не показываются никогда, даже когда показан весь файл. Регион, которого нет в файле, останавливает страницу.

На этом сайте плагин из [Плагинов](/docs/v0/customizing/plugins) это сниппет, `snippets/v0/github-alerts.ts`, с русским вариантом; его регион `types`:

<Snippet id="github-alerts#types" title="custom/plugins/github-alerts.ts" />

```mdx

```

## Текстовые сниппеты [#text-snippets]

Файл `.mdx` (или `.md`) вставляется на страницу как текст: его абзацы, списки, блоки кода и компоненты (`<Callout>`, `<Tabs>`, `<TypeTable>`, компоненты `custom/components/`) становятся собственными у страницы.

- Его строки `import` уходят в начало страницы. Один и тот же импорт на странице и в сниппете остаётся один раз; импорт имени, которое у страницы означает другое, это ошибка.
- В нём могут быть свои теги `<Snippet>`, они читаются для языка и версии страницы. Сниппеты, которые включают друг друга, это ошибка.
- В нём **нет заголовков**: заголовок в сниппете это ошибка. Заголовки страницы и их ид в [реестре якорей](/docs/v0/writing/headings-and-anchors) пишутся на странице; поставьте сниппет под одним из них.
- В нём нет front matter: если он есть, это ошибка.
- Относительная ссылка в нём читается от страницы, на которую он вставлен, и `consify check` её не проверяет. Пишите в сниппете адрес сайта: `/docs/v0/writing`.

`<Snippet>` работает на страницах `.mdx`; на странице `.md` это обычный HTML.

## Языки [#languages]

Сниппет кода это один файл на все языки; когда его комментарии надо перевести, положите вариант в папку языка: `snippets/v1/ru/db/connect.ts`. Вариант меняет только комментарии: `consify check` предупреждает, когда два варианта сниппета кода различаются не только комментариями (`//`, `/* */`, `<!-- -->`, и `#` в shell, Python и YAML; `//` внутри строки тоже считается комментарием). Текстовый сниппет переводится так же, `snippets/v1/ru/prereqs.mdx`.

## Что проверяется [#what-is-checked]

`consify check` и `consify build` (сборка останавливается на ошибке; `--no-snippets-check` пропускает проверку, и тогда сборку остановит сама страница с ошибкой) сообщают:

| Что | Результат |
| --- | --- |
| `<Snippet>` без файла, с регионом, которого нет в файле, или с неверным пропсом | ошибка, со списком проверенных путей |
| Сниппеты, которые включают друг друга | ошибка |
| Заголовок, front matter или `export` в текстовом сниппете, импорт, конфликтующий со страницей | ошибка |
| Папка `snippets/`, которая не версия и не `WITHOUT_VERSION`, файл вне папки версии | ошибка |
| Файл, который не использует ни одна страница | предупреждение |
| Два языковых варианта сниппета кода, которые различаются не только комментариями | предупреждение |

`consify snippets check` это проверка отдельно.

## Найти повторённый код [#find-repeated-code]

```bash
consify snippets find --min-lines 5
```

выводит блоки кода, которые побайтно одинаковы на двух страницах и больше (перевод это другая страница), с местами, где они стоят, файлом для сниппета и тегом, которым их заменить. Команда ничего не меняет; `--min-lines` по умолчанию 3.

## Пример [#an-example]

Страница на двух языках показывает, как подключиться, а у русской комментарии на русском:

```ts title="snippets/v1/db/connect.ts"
import { createClient } from "./client";

// #region open
// one client for the whole app
const client = createClient({ url: process.env.DATABASE_URL });
await client.connect();
// #endregion
```

```ts title="snippets/v1/ru/db/connect.ts"
import { createClient } from "./client";

// #region open
// один клиент на всё приложение
const client = createClient({ url: process.env.DATABASE_URL });
await client.connect();
// #endregion
```

И в `content/en/docs/v1/guide.mdx`, и в `content/ru/docs/v1/guide.mdx` один и тот же тег, под своим заголовком:

```mdx
<Snippet id="db/connect#open" title="db.ts" />
```

Исправление кода делается в `snippets/v1/` один раз; `consify check` предупредит, если русский вариант отстал.
