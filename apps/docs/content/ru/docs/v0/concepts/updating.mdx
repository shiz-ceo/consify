---
title: Обновление ядра
description: Как проект остаётся актуальным
---

```bash
bun update @consify/core @consify/docs @consify/blog @consify/api-reference
```

Обновляйте ядро и используемые фичи вместе (те, которых у вас нет, не указывайте). Так их версии остаются согласованными. Вот и вся процедура. Ваши `docs.config.ts`, `content/` и `custom/` принадлежат вам; пакет никогда в них не пишет. Файлы в `.consify/` пересоздаются при каждом запуске.

## Что может сломаться [#what-can-break]

- **Переименованная или удалённая опция.** Неизвестный ключ считается ошибкой, поэтому запуск останавливается и называет опцию, а не игнорирует её. В заметках к версии сказано, чем она стала.
- **Новая обязательная настройка.** У новых настроек есть значения по умолчанию, поэтому обновление не делает существующий конфиг некорректным.
- **Ваши фичи и компоненты.** Они используют `defineFeature`, React и токены темы. В заметках к версии перечислены все изменения `defineFeature`.

Заметки по версиям см. в разделе [Обновление версий](/docs/v0/upgrading).

## Проверка, что всё работает [#checking-that-it-works]

```bash
bun run typecheck
bun run build
```

Проверка типов охватывает ваш конфиг, ваши фичи и компоненты. Сборка падает при некорректном конфиге, неизвестной категории в посте блога (с `@consify/blog`) или сломанном front matter. `consify check` проверяет контент без сборки: адреса каждой фичи, front matter, переводы и `meta.json`.
