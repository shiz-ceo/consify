`consify add` устанавливает **элемент реестра** — компонент, плагин, фичу, скилл или фрагмент темы,
опубликованный как JSON где-то доступном по HTTP — в ваш проект, так же как компонент shadcn/ui
копируется в проект вместо импорта из пакета. Во время выполнения ничего не импортируется из
`node_modules`; файлы попадают в вашу собственную папку `custom/`, и вы вольны их читать и менять.

```bash
consify add @shiz-ceo/pricing-card    # a namespaced item, from a configured registry
consify add pricing-card              # a bare name, from your default registry
consify add https://acme.dev/r/pricing-card.json   # a full URL, no registry configured needed
```

## Три способа назвать элемент

- **`@namespace/name`** — ищет `@namespace` в `consify.registries.json` и подставляет `name` в
  URL-шаблон этого реестра.
- **Короткое имя** — резолвится к тому реестру, который помечен `"default": true`. Если такого нет —
  понятная ошибка.
- **Полный URL** — используется как есть, вообще без настройки реестра. Способ попробовать элемент,
  на который вам прислали ссылку, ещё до того как настраивать под него источник по-настоящему.

У свежесозданного проекта уже настроен один реестр, `@shiz-ceo`, указывающий на официальные элементы
consify и помеченный как реестр по умолчанию — так что короткое имя заработает сразу, как только в
этом реестре появится что-то опубликованное.

## Настройка приватного реестра

```bash
consify registry add-source @acme https://acme.dev/r/{name}.json
consify registry add-source @internal https://ui.company.internal/r/{name}.json \
  --header "Authorization: Bearer ${COMPANY_REGISTRY_TOKEN}" --default
consify registry list-sources
consify registry remove-source @acme
```

URL обязан содержать буквальный плейсхолдер `{name}` — `consify add` подставляет в него короткое имя
элемента. `--header` можно указывать несколько раз; значение, содержащее `${VAR_NAME}`, читается из
вашего окружения в момент установки и никогда не записывается на диск — сам `consify.registries.json`
можно спокойно коммитить, он хранит только то, какая переменная окружения нужна заголовку, а не её
значение. `--default` делает этот реестр тем, к которому резолвится короткое имя (без `@namespace`);
реестром по умолчанию может быть только один, и добавление нового по умолчанию автоматически снимает
эту отметку со старого.

Удаление источника (`remove-source`) лишь забывает, откуда забирать элементы — оно никак не трогает
уже установленное из него. Для этого нужен `consify remove`.

## Пять типов элементов

| Тип | Куда попадает | Заметки |
| --- | --- | --- |
| `component` | `custom/components/` | Один или несколько файлов, обычно один `.tsx` |
| `plugin` | `custom/plugins/` | Модуль, вызывающий `definePlugin` |
| `feature` | Никуда — это npm-пакет | Ставит `packageName` менеджером пакетов вашего проекта (`bun add` и т. п.), плюс всё из `dependencies`, затем печатает строку, которую нужно добавить в `features` — см. ниже |
| `skill` | `custom/skills/<name>/` | Скилл вашего проекта; `consify skill sync` собирает его так же, как скиллы пакетов `@consify/*` |
| `theme` | `custom/` | Обычные файлы, как `component`/`plugin` — обычно просто `custom/theme.css`, файл, который собственная система тем consify загружает после своих токенов |

Элемент типа `feature` — это всегда «поставить пакет, затем включить его», никогда не копирование
файлов. Настоящая фича вроде блога — это пакет со своими страницами, опциями и скиллами, который
корректно работает только как нормально версионируемый, обновляемый npm-пакет,
поэтому `consify add blog` выполняет `bun add @consify/blog` (или менеджер пакетов вашего проекта) и
печатает:

```ts
import { blog } from "@consify/blog";
features: [..., blog()],
```

`docs.config.ts` **не** редактируется автоматически — эту строку вы вставляете сами. Запись в
`consify.registry-lock.json` всё равно появляется (с пустым списком файлов, так как на диск ничего
не записывалось), поэтому `consify list` покажет элемент установленным, а учёт
`registryDependencies` продолжит работать. `consify remove` для `feature`-элемента удаляет только
эту запись в lock-файле — она печатает напоминание, что сам npm-пакет **не** удалён (при необходимости
выполните `bun remove @consify/blog` сами), точно так же, как команда уже оставляет нетронутыми любые
другие `dependencies`, добавленные элементом.

Элемент может объявлять `dependencies` (npm-пакеты, устанавливаемые тем же менеджером пакетов, что
уже использует ваш проект — для `feature`-элемента в дополнение к самому `packageName`) и
`registryDependencies` (другие элементы реестра, устанавливаемые первыми, рекурсивно) — установка
одного элемента, зависящего от двух других, ставит все три, в правильном порядке.

Установка элемента `skill` печатает напоминание запустить `consify skill sync` после этого — именно
это реально копирует новый скилл в `.claude/skills/`, чтобы его увидел Claude Code; `consify add`
только пишет файл, но никогда сам не запускает `sync` — это отдельный, явный шаг (см.
[Скиллы для Claude](/docs/v0/customizing/skills)). Элемент `feature` не приносит своих файлов;
скиллы его пакета, в `skills/<name>/`, подхватывает тот же `consify skill sync`.

## Что установлено: lock-файл

Каждый `consify add` пишет в `consify.registry-lock.json`, рядом с `consify.registries.json`, — хеш
содержимого каждого файла на момент установки, чтобы позже `consify add`/`consify remove` могли
отличить «не менялось с установки» от «вы это отредактировали» от «вообще не наше». Коммитьте его,
как `bun.lock` — это состояние проекта, которым стоит делиться с командой.

```bash
consify list          # or: consify registry list — the same command, listed under both names
consify remove @shiz-ceo/pricing-card
```

`consify list` помечает файл как `modified`, если он больше не совпадает с записанным хешем, или
`missing files`, если его удалили вручную. `consify remove` удаляет установленные им файлы (пропуская
— с предупреждением — всё, что изменено вручную, если не указан `--force`) и запись в lock-файле;
если от него всё ещё зависит другой установленный элемент, команда откажется, если не передать
`--force` и туда тоже. Ни одна из команд не трогает npm-`dependencies`, добавленные элементом —
подчищать их оставлено вам.

## Что стоит знать об особых случаях

- **`consify add` дважды для одного и того же спецификатора**: без изменений — это no-op; при
  локальных изменениях — отказ без `--force`; `@ns/name` и эквивалентный полный URL отслеживаются как
  *две отдельные* записи в lock-файле, даже если резолвятся в одно и то же место — lock-файл
  записывает, как вы попросили, а не канонизированную идентичность.
- **`consify.registries.json`, который существует, но не парсится или не проходит валидацию** — это
  ошибка для любой команды, которая его читает, даже той, которой он не нужен (как `consify add
  <full-url>`) — сломанный конфиг стоит показать сразу.
- **`@consify/core` установлен без `@consify/cli`** (старый lock-файл, или удалили намеренно): `consify`
  перестаёт быть распознаваемой командой на уровне шелла — та же форма отказа, что при удалении
  пакета любого CLI-инструмента с сохранением его библиотеки.
