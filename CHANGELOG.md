# Changelog

All notable changes to `consify` are documented here. Format: [Keep a Changelog](https://keepachangelog.com/), versioning: [SemVer](https://semver.org/).

## [Unreleased]

- **One `defineFeature`:** a section of the site is one object — React pages by address, `load` for data, `files` for feeds and JSON, strings with `t`, and `content` for MDX files. Core reads the content (front matter checked by a schema, translations, fallback), compiles MDX on the server (`<Mdx code />`), and makes the sidebar, the search, `llms.txt`, social images and the RSS feed of it; a page per file is `entry: true`. Routes, pre-render, the sitemap and the header link come from the feature. `extensions` is now `features`; `plugins`, `components` and `twoslash` are under `mdx`; `defineInstanceFeature`, feature `node.ts` modules, generated `consify:<id>` modules and fumadocs-mdx are gone. `docs()`, `blog()` and `apiReference()` are built on it (a second one is `docs({ id: "guides" })`). The front page is `content/<language>/home.mdx` or a feature with `path: ""`. `consify docs check` is `consify check`. Addresses moved under their section: `/{lang}/docs/llms.txt`, `/{lang}/docs/og/<page>.png`, `/{lang}/blog/og/<slug>.png`, `/{lang}/<id>/search.json`; the API reference link id is `api`.
- **The CLI is its own package, `@consify/cli`:** `dev`/`build`/`typegen`/`start`, `deploy`, `doctor`, `docs check`, `skill sync`/`skill list`, `lang add`/`lang status`, `links` and `locale` all moved out of `@consify/core` into a new package (the `consify` bin name is unchanged — installing `@consify/create`'s generated project or adding `@consify/cli` yourself is all that's needed; nothing about typing `consify <command>` changes). Argument parsing moved from hand-rolled `args.includes("--force")`/`args.indexOf("--name")` checks to [commander](https://www.npmjs.com/package/commander) with [zod](https://zod.dev/)-validated options, so every command now has real `--help` text. **Breaking for anyone importing `@consify/core/node`'s command entry points directly** (`runDeployCommand`, `runDoctorCommand`, `runDocsCommand`, `runSkillCommand`, `runLangCommand`, `runLinksCommand`, `runLocaleCommand`, `runServeSocketCommand`, `deployTargets`/`findTarget`, `DeployContext`/`DeployFile`/`DeployTarget`) — none of these are public exports of any package anymore, since `bin/consify` and the command implementations now live in the same package with nothing to export across.
- **A registry, shadcn-style:** `consify add <specifier>` installs a component, plugin, feature, skill or theme snippet — published as plain JSON, copied into your own `custom/` folder rather than imported from `node_modules` — from `@namespace/name`, a bare name (your default registry), or a full URL. `consify registry add-source`/`remove-source`/`list-sources` manage `consify.registries.json` (safe to commit — a header value referencing `${ENV_VAR}` is only ever resolved from your own environment at install time, never written to disk). `consify list`/`consify remove` read and act on `consify.registry-lock.json`, tracking a content hash of every installed file so a later install or removal can tell "unmodified" from "you edited this" from "not ours at all" — the same overwrite protection `consify skill sync` already had, generalized. A freshly scaffolded project comes with one registry configured, `@shiz-ceo`, pointing at consify's own official items. See [Registry](/docs/v0/customizing/registry).
- **Content in language folders:** every language has its own folder, `content/<language>/` with `docs/`, `blog/` and `home.mdx` inside, and a translation has the same path as the original (the default language has a folder too). A `meta.json` in a language folder translates the menu, the keys that are not text come from the default language. `docs({ editOnGithub: { contentDir } })` is now the folder that holds the language folders (default `content`). The suffix layout (`page.ru.mdx`, `meta.ru.json`, `home.ru.mdx`) is gone. New commands: `consify lang add <language> [--copy]` prepares a language, `consify lang status [language] [--missing]` shows what is left to translate.
- **Links:** sections only offer a catalog of links (`Feature.links`, ids like `docs`, `blog`, `blog:rss`, `api-reference`), and the site chooses them with `header.links` and `footer.columns`. Items are catalog ids, ids with replaced titles or own addresses, and the header takes drop-down menus with descriptions. An id also works in the `href` of the home page buttons. The top-level `nav` option and `Feature.nav` are removed. New command `consify links [language]` prints the catalog.
- **Search:** every section has its own search in one dialog, a field at the top of the sidebar (the docs and the API reference; on small screens the sidebar opens from its button). A feature provides only data: `Feature.search` is a module with `useSearch`. The blog search is the search box on the blog list page.
- **Header and footer independence:** one `SiteFooter` for every section (no more per-section variants), and `SitePage` (was `SiteLayout`) takes a single `sidebar: boolean` prop instead of any header or footer options. A feature that needs to react to the sidebar (the API reference's own panel) uses `useSidebarCollapsed()` or the `data-consify-sidebar-collapsed` attribute instead of reaching into Fumadocs internals.
- **Deploy and CLI:** `consify deploy` writes what a hosting target needs — `github-pages`, `cloudflare-pages`, `netlify`, `vercel` (static hosts, each with a real root redirect instead of a meta-refresh page), and two self-host targets, `docker` (an nginx-only image for a static build, `node:22-alpine` for a server one, never publishing a port — only reachable from a shared nginx over a Docker network) and `nginx` (an `include`able fragment, HTTP/3 on by default, `--socket` to bind a Unix socket instead of a TCP port, with a generated systemd unit). No target, in a real terminal, asks instead of just listing. `consify doctor` checks the Node version, that every `@consify/*` package matches, and the config. `consify --version` prints every installed `@consify/*` package.
- **CI/CD:** `docker`/`nginx --ci` also write a GitHub Actions workflow: on every push that touches the site, it runs `doctor`, `typecheck` and `build` (a broken page fails the build, so nothing bad ships), then deploys over SSH — `docker` builds and pushes an image to `ghcr.io` and runs `docker compose pull && up -d` on the server, `nginx` uploads a new release and swaps the `current` symlink (restarting the systemd unit for a server build), pruning old releases.
- **A skill for every feature:** the single `consify-docs` skill is now an orchestrator (`consify`) plus one skill per feature that has something specific to teach — `consify-docs-authoring`, `consify-blog-authoring`, `consify-api-reference-authoring`, and `consify-theme` for the look. A feature (built in or your own, in `custom/features/<id>/`) offers one by shipping a `skill/SKILL.md` next to its `feature.ts`; `consify skill sync` collects the ones the project's `extensions` actually use into `.claude/skills/` (`consify skill list` previews it), and never overwrites a folder it did not create without `--force`. `@consify/create` runs it after install instead of baking in a fixed skill. Also new: `consify docs check`, the content checker (translations, `meta.json`, front matter) as a public command, not just this repository's own `bun run docs:check`.
- **Three more core skills:** `consify-translate` (translation as its own entry point, with a glossary file that persists across requests instead of just being offered once), `consify-upgrade` (matches the changelog between the installed and target version against the actual project — a catalog of known migrations with detection and fix for each, not just "read the changelog yourself"), and `consify-content-audit` (finds docs that mention a since-removed identifier, or that are older than the code they describe — a heuristic report, on request only, never automatic). A fifth, `consify-extension-engineering`, is for building a whole new extension package the way `@consify/docs`/`@consify/blog`/`@consify/api-reference` are built, distinct from a small `custom/features/` section. `CHANGELOG.md` now ships with every published package (`consify-upgrade` reads it from there).

- **Head and scripts:** `head` in `docs.config.ts` adds meta tags, links and scripts to the `<head>` of every page (server, static and 404), an object or a function of the language. The docs have recipes for Plausible, Umami, Google Analytics, Yandex Metrika and Cloudflare Web Analytics.
- **Banner:** `banner` shows a closable announcement above the header (text per language, optional link and `id`, `info` or `warning`); a closed banner is remembered in the browser.
- **Theme presets and brand color:** `theme.preset` (`neutral`, `ocean`, `forest`, `sunset`, `violet`, `paper`, `mono`) and `theme.brand` (one hex color that makes the accent of both color schemes). Order: preset, brand, then `colors`, `radius` and `fonts`.
- **Accessibility:** every text pair of every preset and brand color passes WCAG AA in both color schemes. The muted text color is darker (`#6b6b6b` on light), and code uses the `github-light-high-contrast` and `github-dark-default` themes; Twoslash error lines and removed diff lines were adjusted.
- **Tests and CI:** end-to-end tests with Playwright (`bun run e2e`, the `e2e` job in CI) and the `compat.yml` workflow (unit tests on Ubuntu, Windows and macOS; the packed packages installed with npm and pnpm on Node 22 and 24).

## [0.1.0] - not released yet

The first version.

- **Docs** (`@consify/docs`, installed on its own and listed in `extensions` as `docs()`): MDX pages from `content/<language>/docs`, sidebar from folders and `meta.json`, table of contents, search (server endpoint or a static index), previous and next links, Edit on GitHub, `llms.txt`, generated social images, sitemap and `robots.txt`.
- **Interface languages:** the strings of the interface live in language packs. English and Russian ship with consify (Russian also translates the Fumadocs widgets), any other language is a file `custom/locales/<language>.ts` (or `.json`) made by `consify locale <language>` with every string to translate. Plugins and extensions bring their own strings, `useMessages()` reads them in a component, and `i18n.messages` overrides one string. `@consify/create` makes a pack for the languages it has no strings for, and the console warns about a language without one.
- **Languages and versions:** translations in language folders (`content/<language>/…`), `i18n.fallback` for pages without a translation (`notice`, `show`, `hide`), several versions of the docs (`docs({ versions })`) with a switcher and a deprecated banner. The docs options (`versions`, `toc`, `breadcrumbs`, `pagination`, `llmsTxt`, `og`, `editOnGithub`) are options of `docs()`.
- **Extensions:** `extensions` in `docs.config.ts` adds sections to the site. `defineFeature` (routes with parameters, resource routes, redirects, several links, strings per language, MDX components, pre-render and sitemap) is the same API the docs, the blog and the API reference use, so a project adds its own in `custom/features/`.
- **Core** (`@consify/core`): the config, the layout (home page, header, footer), the theme, the MDX pipeline and the build. It has no sections of its own; a site without `docs()` works (for example a blog only), and without a home page `/{lang}` redirects to the first link of the header. Search belongs to a section.
- **Blog** (`@consify/blog`, installed on its own): categories, tags, authors, search, numbered pages, RSS, social images, reading time; drafts and future posts are never compiled.
- **API reference** (`@consify/api-reference`, installed on its own) from an OpenAPI schema (Scalar).
- **Customization:** theme tokens, plugins (remark, rehype, Shiki), custom MDX components, slots for the home page (`custom/home.tsx` or `content/<language>/home.mdx`), header and footer, a footer with columns and social icons.
- **Code and diagrams:** highlighted lines and diffs, tabs, type-checked `twoslash` blocks, KaTeX, Mermaid styled with the theme of the site.
- **Deployment:** a Node server or plain static files (`deploy.mode`), `deploy.basePath`.
- **Tooling:** the `consify` CLI (`dev`, `build`, `start`, `typegen`), the `@consify/create` generator, and the `consify-docs` skill for Claude.
